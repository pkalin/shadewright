# ADR-0015: Analysis records are kept and outlive the lab

- Status: Accepted
- Date: 2026-11-01

## Context

Model transcripts (context sent, tool calls, outputs, tokens) are needed for audit, for debugging bad proposals, and for building the evaluation set. The lab cluster is destroyed after every session.

## Decision

- The analyzer writes one record per analysis, after redaction, through the `AnalysisStore` interface.
- In the lab the store is a blob container in the `foundation` Terraform root, not in `lab`, so records survive `terraform destroy` of the cluster. A lifecycle rule deletes records after a fixed retention.
- The analyzer's identity may only create blobs in that container. Nothing else in the cluster can read them.
- In other clusters the store is on by default and configurable; only redacted data is ever written.

## Consequences

- Real incidents from the lab become evaluation fixtures.
- Storage cost is negligible at lab volume, but retention must be set.
- The deployed role does not yet enforce create-only: see the amendment of 2026-11-04.
- A redaction bug would now persist data, so redaction gets its own tests and is applied before both the model call and the write.

## Alternatives considered

- Drop transcripts after analysis: no audit trail and no evaluation data.
- Store them in the cluster: lost with the lab, and too large for etcd.

## Amendments

- 2026-11-04: the Decision (create-only) is unchanged, but the analysis writer role deployed in `shadewright-azure` does not enforce it. It grants `blobs/write`, which can overwrite an existing blob. Blob versioning is on, so an overwritten record keeps its earlier content as a version until retention removes it: today the guarantee is versioning as recovery evidence, not create-only. Making the role create-only is tracked in [#154](https://github.com/pkalin/shadewright/issues/154); immutable blob storage is an option there ([#244](https://github.com/pkalin/shadewright/issues/244)).
- 2026-11-17 ([#845](https://github.com/pkalin/shadewright/issues/845)): the Decision is unchanged; this records how redaction, which every record and every model call relies on, is applied. Redaction decides once, on one canonical view of the text as it was read: every Unicode space, control and format character and every invalid byte counts as indentation, LF, CRLF and a lone CR end a line, and nothing is replaced, escaped or cut to make the view. Every rule reports spans of the original bytes, and the spans are merged and replaced once, so no rule reads another's output. No caller redacts text it has already encoded, escaped, cut or repaired; a sequence of strings is decided as a whole: a caller that holds the strings (`redact.Strings`, also the name and value of a metric label in `query_metrics`) gets the decision String takes on the strings joined by line breaks, mapped back to each string, so what String hides in the strings joined, Strings hides in them apart by construction, and one function adds what a joined text does not show as a key and value, for that caller and for a sequence written in a text. The rules also read a folded view where a reader sees another text than the bytes (an invisible character inside a key name or before its separator, a colon look-alike from Unicode's confusables list, an explicit YAML key, a separator of other characters after a secret key; the invisible characters and the colon look-alikes are classes generated from the Unicode data, not lists of forms found so far), in a text and in each string of a sequence, and a match on it counts on the bytes it was folded from; this is a second reading of the same text, not a pass over another's output. The two remaining second looks are on text that only lost characters: the context builder and the log tool redact the excerpt of any `LogSource` at their boundary, since a source may not redact, and the fingerprint redacts its stored symptom until it no longer changes (design 10.3). Alternative not taken: more passes in a fixed order, each redacting what an earlier step had escaped, flattened, repaired or cut. #840 went that way, and each new step needed its own pass and its own place in the order; a form one pass rewrote (a `>` sanitized to `)`, a line break escaped by JSON, a key line dropped by a cut) hid a secret from the next pass, and the result depended on the order, which no test can cover for every caller. One view read once has no order to get wrong, and its cost is counted (`redactwork`): about three quarters more work per byte than main on the corpus of #845 (46.8 steps against 27.3 on its 14,310 inputs, 1.72 times, as `TestCanonCorpusWorkIsLinear` prints them), within the same budget of 1,024 steps per byte.
- 2026-11-18 ([#845](https://github.com/pkalin/shadewright/issues/845), third decision; replaced by the sixth and seventh decisions): the Decision is unchanged. A tool result is decided as one text: each read tool lays out the values it shows (the fields in document order as `name: value` lines, the strings of a list as lines of their own, nothing escaped or encoded), `redact.Pieces` takes the one decision on that text, and each value gets its part back before the result is encoded. No field, list or map is decided by itself, and the encoded answer is not redacted again, so a key in one field and its value in a sibling or the next field (an HTTP header's name and value, a flag at the end of a command and its value in the arguments) are seen together, as main's second pass over the whole answer saw them. The string after a secret flag is always its value (`["--token", "--verbose"]` hides `--verbose`). Cost, as the tests print it with `redactwork`: `get_resource` on a large pod takes less work per byte than main with its second pass (the figures are in the entry of the sixth decision); `{password: marigold` followed by 512, 1,024 and 2,048 closing braces takes 21,325, 41,805 and 82,765 steps (`TestTokenShapesWorkIsLinear`; 152,137, 565,577 and 2,178,889 before, when each brace read the rest of the line again).
- 2026-11-18 ([#845](https://github.com/pkalin/shadewright/issues/845), fifth decision; replaced by the sixth and seventh decisions): the Decision is unchanged. Where the object gives the key and the extent of a value, redaction uses them: each value of a tool result carries the key the object gives it (a map key, a field name, a metric label's name), and a key that is a secret key by main's rule for a quoted key (`redact.SecretKey`, so `auth` and `pass` count whatever the value looks like) hides the whole value, line breaks, blanks and markers included. Where a value holds a line break, the laid-out text is also read with the line breaks inside values written as JSON escapes, the text main read in its pass over the encoded answer, so a value runs on over the line breaks of its string where main's reading did, and a value that reading takes as the value of a key outside it (an HTTP header's value after its name) is hidden to its end. A map keeps every entry: two keys redacted alike get ` (2)`, ` (3)`. The laid-out text stays for relations between fields and for what is inside a value. Laying out a map sorts its keys, the one step that is not linear: O(n log n) comparisons, each reading at most the start two keys share (`TestMeasureMapKeySort`, a measurement). Cost, as the tests print it with `redactwork`: `get_resource` on a pod of 64 and 256 containers took 31.1 and 31.2 steps per byte of the pod as JSON at that build, 57.7 on main (`TestGetResourceWorkIsLinear`, main's figure from `testdata/getresource-main-work.tsv`, written at c84029ce by `TestWriteGetResourceMainWork`).
- 2026-11-18 ([#845](https://github.com/pkalin/shadewright/issues/845), sixth decision): the Decision is unchanged. The text decided on is the text a tool returns: each read tool writes its answer as pieces (the text it writes, and each value written as the answer writes it, on a line or as the content of a JSON string), and `redact.Pieces` decides those bytes as main's two passes did, each value alone as it was read first, then the answer with those markers, so a pattern that exists only in the returned line is seen (`Warning Bearer Pod/<name>` hides the name) and String over a returned result hides no value more. Where the object gives the key, the whole value is hidden and nothing beyond it (a block value under a secret map key takes no later entry). A key found inside a value hides as far as main hid at that tool: at `list_events` the rest of a note after the line of the key stays, at `get_resource` a `\n` does not end the value and the next blank does. A list of URLs in angle brackets before an address is hidden whole up to the `@` again, as on main (showing more is [#860](https://github.com/pkalin/shadewright/issues/860)). Map keys decided alike are renamed with one counter per key, which is linear. Cost, as the tests print it with `redactwork`: `get_resource` on a pod of 64 and 256 containers takes 46.1 steps per byte of the pod as JSON at both sizes, 57.7 on main (`TestGetResourceWorkIsLinear`); String does 46.8 steps per byte on the canonical corpus, 27.3 on main (1.72 times); the token shapes are unchanged (21,325, 41,805 and 82,765 steps). The sorts and their bounds are listed in [design 10.3](../design/10-security.md#103-redaction).
- 2026-11-18 ([#845](https://github.com/pkalin/shadewright/issues/845), seventh decision): the Decision is unchanged. The pieces of `get_resource` are the string tokens of the JSON it returns: the object is encoded once and the tokens of that output are walked in one pass, every string token that is a value or a map key is a piece in its place, with its key and path from the tokens around it, and its text is the string of the object as it was read (an invalid byte stays an invalid byte). A type that writes its own JSON (an int-or-string, a quantity, a time, raw content) is tokens like any other, so a probe port written as `--password V` hides `V` as on main; the layout before put a stand-in for every string and mapped the stand-ins back, which left those strings out and grew quadratic on values made of the stand-in character (a pod of 89 KB allocated 1,975 MB; 30 MB now). The walk counts its work with the redactor's (`redact.Tick`). A reference is not a value: the name and key of a `secretKeyRef` or `configMapKeyRef` and the names of `envFrom` sources show as on main, and the names under a secret-named field stay hidden as on main (a stored table from main, 1,035 identifiers, none differing). Cost, as the tests print it with `redactwork`: `get_resource` on a pod of 64 and 256 containers takes 46.2 steps per byte of the pod as JSON at both sizes, 57.7 on main (`TestGetResourceWorkIsLinear`); pods of runs of private use characters, quotes, backslashes and escaped quotes take 47.0 steps per byte from 8.7 KB to 68 KB (`TestGetResourceLayoutWorkIsLinear`); String does 46.8 steps per byte on the canonical corpus, 27.3 on main (1.72 times); the token shapes are unchanged (21,325, 41,805 and 82,765 steps).
- 2026-11-18 ([#845](https://github.com/pkalin/shadewright/issues/845), eighth decision): the Decision is unchanged. A map key is a piece like a value: main redacted no key alone, only its JSON answer, so a key is also decided as the answer writes it (a line break is `\n` there), and a `volumeAttributes` key holding a connection string, a line break and more text is hidden to its end as on main (5,096 key placings in 13 value shapes, 756 shown that main hid before, none now). Numbers, booleans and null are tokens of the walk: inside a collection main hid whole, or under a secret key, each is written as a JSON string holding the marker, so a Secret volume's `defaultMode` and `optional` are hidden as on main and the answer stays JSON (940 placings, 44 shown that main hid before, none now). Two map keys the encoder writes alike (keys that are not valid UTF-8, which the API server refuses) make `get_resource` answer that it could not fetch the object; that is the safe side and stays, returning the object is a follow-up.
- 2026-11-18 ([#845](https://github.com/pkalin/shadewright/issues/845), ninth decision): the Decision is unchanged; this replaces "as main's two passes did" in the entries of the sixth and seventh decisions. No reading of a tool result takes another reading's output as its only input. `redact.Pieces` hides the union of three readings of the same answer: each piece alone, the whole answer as the tool writes it, and the whole answer with the markers of main's first pass in place (each value that is no map key redacted alone as it was read), which is what main's second pass read. The readings only find spans, and nothing is replaced until all three have run. A map key that is a connection string, a line break and `-authorization` had been hidden as a piece before the answer was read, which took away the word that hides the value under it; `get_resource` showed that value and main hid it. The second reading adds over-redaction: 6,362 kept pieces of the canonical corpus that main keeps are lost (`list_events` 3,934, `get_resource` 2,428), 19,750 in the stored table against 13,388 without it, all of them text after the secret on the later lines of a value with line breaks, which the answer writes on one line or with `\n` escapes. Cost, as the tests print it with `redactwork`: `get_resource` on a pod of 64 and 256 containers takes 81.6 and 81.7 steps per byte of the pod as JSON, 57.7 on main (`TestGetResourceWorkIsLinear`); the pods of `TestGetResourceLayoutWorkIsLinear` take 80.1 steps per byte from 8.7 KB to 68 KB, and the allocation stays about 400 bytes per byte (`TestGetResourceMemoryIsLinear`); String is unchanged (46.8 steps per byte on the canonical corpus).
