# ADR-0015: Analysis records are kept and outlive the lab

- Status: Accepted
- Date: 2026-11-01

## Context

Model transcripts (context sent, tool calls, outputs, tokens) are needed for audit, for debugging bad proposals, and for building the evaluation set. The lab cluster is destroyed after every session.

## Decision

- The analyzer writes one record per analysis, after redaction, through the `AnalysisStore` interface.
- In the lab the store is a blob container in the `foundation` Terraform root, not in `lab`, so records survive `terraform destroy` of the cluster. A lifecycle rule deletes records after a fixed retention.
- The analyzer's identity may only create blobs in that container. Nothing else in the cluster can read them.
- In other clusters the store is on by default and configurable; only redacted data is ever written.

## Consequences

- Real incidents from the lab become evaluation fixtures.
- Storage cost is negligible at lab volume, but retention must be set.
- The deployed role does not yet enforce create-only: see the amendment of 2026-11-04.
- A redaction bug would now persist data, so redaction gets its own tests and is applied before both the model call and the write.

## Alternatives considered

- Drop transcripts after analysis: no audit trail and no evaluation data.
- Store them in the cluster: lost with the lab, and too large for etcd.

- 2026-11-04: the Decision (create-only) is unchanged, but the analysis writer role deployed in `shadewright-azure` does not enforce it. It grants `blobs/write`, which can overwrite an existing blob. - 2026-11-17 ([#845](https://github.com/shadewright-labs/shadewright/issues/845); changed by the thirteenth decision, which keeps the reading of the release before as one more reading of every text, and by the fifteenth, which makes `redact.Strings` hide what `String` hides in the strings joined with no match ended at a line break inside a string): the Decision is unchanged; this records how redaction, which every record and every model call relies on, is applied. Redaction decides once, apart from the two second looks named below, on one canonical view of the text as it was read: every Unicode space, control and format character and every invalid byte counts as indentation, LF, CRLF and a lone CR end a line, and nothing is replaced, escaped or cut to make the view. Every rule reports spans of the original bytes, and the spans are merged and replaced once, so no rule reads another's output. No caller redacts text it has already encoded, escaped, cut or repaired; a sequence of strings is decided as a whole: a caller that holds the strings (`redact.Strings`, also the name and value of a metric label in `query_metrics`) gets the decision String takes on the strings joined by line breaks, mapped back to each string, so what String hides in the strings joined, Strings hides in them apart by construction, and one function adds what a joined text does not show as a key and value, for that caller and for a sequence written in a text. The rules also read a folded view where a reader sees another text than the bytes (an invisible character inside a key name or before its separator, a colon look-alike from Unicode's confusables list, an explicit YAML key, a separator of other characters after a secret key; the invisible characters and the colon look-alikes are classes generated from the Unicode data, not lists of forms found so far), in a text and in each string of a sequence, and a match on it counts on the bytes it was folded from; this is a second reading of the same text, not a pass over another's output. The two remaining second looks are on text that only lost characters: the context builder and the log tool redact the excerpt of any `LogSource` at their boundary, since a source may not redact, and the fingerprint redacts its stored symptom until it no longer changes (design 10.3). Alternative not taken: more passes in a fixed order, each redacting what an earlier step had escaped, flattened, repaired or cut. #840 went that way, and each new step needed its own pass and its own place in the order; a form one pass rewrote (a `>` sanitized to `)`, a line break escaped by JSON, a key line dropped by a cut) hid a secret from the next pass, and the result depended on the order, which no test can cover for every caller. One view read once has no order to get wrong, and its cost is counted (`redactwork`): about three quarters more work per byte than main on the corpus of #845 (46.8 steps against 27.3 on its 14,310 inputs, 1.72 times, as `TestCanonCorpusWorkIsLinear` prints them), within the same budget of 1,024 steps per byte.

Every entry point of package `redact` (`String`, `StringKeeping`, `Clean`, `Replace`, `StringTwice`, `ReplaceFrom`, `ReleasedText`, `Strings` and the `Pieces` family) takes one decision on one entry (a text, the strings of a sequence, the pieces of an answer with their keys) and counts its steps where the linearity tests count them, the reading of the release before (package `released`) included, and each comparison of a sort of spans, ranges or flow brackets in either package (`sortFunc`, so a sort with no budget left stops; `TestEverySortCountsItsComparisons`), and each byte the engine of a rule's regular expression reads, attempt by attempt (`meter.Expr`: an expression shaped like `a.*z|a` reads the rest of the text on every match attempt, so on 32 KiB of `a` it ran 15 s inside a budget it had passed, counted once per call; it is withheld in about half a second now, `TestExpressionRescanIsChargedPerAttempt`, with the same matches as `FindAllStringSubmatchIndex`, `TestFindAllIsFindAllStringSubmatchIndex`), on a meter of its own (`internal/redact/meter`, threaded through both packages; the kept files of `released` are the release's code with the linearity change of commit `1ecea23` (`released/redact.go` and `released/extent.go` changed, `released/lines.go` new), pinned with the meter taken out by `TestReleasedIsTheReleaseBefore`; their output equals that of the code before the change, kept in `released/testdata/v052`, by the tests of `released/kept_test.go` and `TestReleasedSpansMatchKeptCopy`, and the release's stored results by `TestReleasedReproducesTheReleaseBefore`). The budget is linear in the size of the entry: 1,024 steps per byte (`redact.WorkPerByte`) and 65,536 for the fixed cost of a call (`redact.WorkFixed`). The factor comes from the largest cost measured on the corpus tables (every input of `releasedInputs`, the forms of the canonical corpus, the staircases at 64 KiB and the lines of repeated quoted keys, at every entry point): 284.5 steps per byte, `Strings` on the staircase of `pass​: |`, so the budget is 3.6 times that, and every input of those tables uses at most half of it (`TestBudgetFactorCoversTheCorpus`). An entry longer than 4 MiB (`redact.MaxEntry`), above the 3 MiB the API server accepts in one request body and so above any object that can exist (an object stored is smaller still: about 1.5 MiB with etcd's default request limit, design 10.3), is withheld before any work. An entry withheld, by its size or by its budget, is withheld whole: the caller gets the fixed marker `[REDACTED:withheld]` and nothing of the entry, whatever point the work had reached (`TestBudgetDecidesWholeOrWithholdsWhole` stops each entry point, `Replace` and `PiecesFitting` included, at sampled budgets below what it needs: every budget up to 64 steps, about 200 spread over the rest, and one step short), and a flag that says so. A caller tells a withheld entry by that flag, never by comparing a text with the marker, so a log line or a value that spells `[REDACTED:withheld]` is ordinary text and cannot blank a section or fail a read: `StringChecked`, `StringTwiceChecked`, `ReplaceChecked` and `StringsChecked` are the text forms with the flag, `ReplaceFrom`, `PiecesWithin` and `PiecesFitting` always return it, and the Flux status reader passes it on as `DeliveryStatus.MessageWithheld` (`TestWithheldIsAFlagNotAText`, `TestALogThatSpellsTheMarkerIsText`, `TestRenderLogMarkerTextIsNotWithheld`, `TestDeliveryMessageThatSpellsTheMarkerIsText`, `TestStatusReaderFlagsAWithheldMessage`, and a hint that spells the marker is stored as text); an entry inside its budget is decided exactly as before, so the budget only ever shows less. The metric `shadewright_redaction_withheld_total` counts each by `reason` (`work`, `size`). The callers show it as a source that failed: a read tool's result is "could not fetch: withheld by redaction" with the label `withheld by redaction` and no values (`get_resource`, `list_events`, `check_missing_reference`, `query_metrics`, `get_delivery_status`, and `get_pod_logs`, where the log source returns `providers.ErrWithheld`); a log excerpt whose header is withheld, or a value in it (the pod UID or the container ID of the instance), is withheld as a withheld body is, in the context builder and at `get_pod_logs` alike (`RenderLog`, `TestRenderLogWithheldHeaderValue`); a context block is "could not fetch" with that label, and its section counts as a failed source, which escalates; a reviewer hint redaction withholds is refused as not redactable; a symptom note withheld fingerprints as a note too long to read; `Clean` answers false, so the analysis store refuses a record it cannot check, for good. Four callers keep the text form and show the marker in place of the value, as text: never the value, and the metric counts it. They are the fields of an analysis record (`StringKeeping` on each field in `internal/analysis/record.go`; the record stays checkable, since `Clean` takes the exact marker `[REDACTED:withheld]` as a marker wherever it stands, and not its short form or a look-alike, `TestCleanTakesTheWithheldMarker`), the model text written to the analyzer's log (`run.redact`), a branch name from the code host in a condition message (`hostBranchText`), and a module's evidence value cut to its bound (`boundValue` in `internal/modules`). - 2026-11-22, heap ([#1087](https://github.com/shadewright-labs/shadewright/issues/1087), decisions of 2026-11-22: the heap of redaction is budgeted from the worst measured case, not bounded shape by shape; this entry was revised the same day, after the decision's last rows, for the worst measured shape, the property and the room as the tests enforce them, the collector, which no longer reads a long note, and the record check inside the store's tries): the Decision is unchanged. **The bound of one entry stays.** `redact.HeapPerByte` (28) and `redact.HeapFixed` (4 MiB) and the reason `heap` for pieces and strings are as in the entry of 2026-11-21. They are the bound of the shapes the heap tests list as within it, not of every shape: on text dense in matches or in control characters one entry holds more, measured. The run of slashes is fixed: the kept reading of base64 windows (package `released`, edited for this alone, `TestSlashWindowsMatchKeptCopy` comparing it with the kept copy of v0.5.2) holds no part for an empty run between slashes, so 1.5 MiB of slashes holds between 1.1 and 6.1 MiB by entry point, from 135 MiB. **Measured worst case.** `TestHeapPerByteOfEveryShapeStrings`, `...Twice`, `...Sequences` and `...Pieces` (they replace `TestHeapOfOneEntryIsBounded`) measure the peak live heap of every entry point on every shape known, at 64 KiB, 512 KiB and the largest entry (1.5 MiB; 1 MiB for `ReplaceFrom`), and log the heap per byte past `HeapFixed`. The worst is 71.7 bytes per byte: `PiecesWithin` and `PiecesFitting` on an address followed by a control byte (the shape "addresses and control" of the test table) repeated at 1.5 MiB (111.6 MiB). `redact.HeapWeightPerByte` is 100: the tests and the weekly fuzz target `FuzzHeapWithinWeight` (a fuzzed unit repeated to 192 KiB) fail when an entry holds more than 75 bytes per byte past `HeapFixed`, a margin of 25 percent. **Redactions at once.** Every ordinary entry point takes, before its decision, a weight of `HeapFixed` plus `HeapWeightPerByte` per byte of its entry from a process-wide weighted semaphore, and gives it back on every return and on a panic. The limit is half of the Go memory limit (`GOMEMLIMIT`); without one it is 64 MiB, logged once, so the limit is never off. An entry whose weight is over the limit takes all of it and runs alone; waiters are served in order. **Property, as the tests enforce it:** the entries running at once hold at most the larger of the limit and one entry at the tests' line (4 MiB plus 75 bytes per byte: 116.5 MiB at 1.5 MiB; `TestRedactionsAtOnceStayUnderTheLimit`), plus the collector's short entries, at most 4 MiB. The weight of an entry depends on its size, not on its content, so a shape heavier than 100 bytes per byte, if one exists, holds more than its share until the constant is raised in a release. **A wait** ends with the context of the caller where one reaches the redactor (`Redactor.WithContext`: the read tools pass the context of the call with its timeout, the context builder the build's deadline, the log source the read's, the analysis store one of at most a try's timeout for each try) and after 2 minutes in every case. An entry whose wait ends is withheld with the reason `wait` and shown as a source that failed, which escalates like any failed read (decision of 2026-11-20 on #873). The analysis record's check runs inside the store's tries: a try whose check waited sends nothing and the next one checks again; when every try waited, the record is not written, counted `failed`, and the Warning event says the check waited on every try. A wait never refuses a record. **The collector never waits.** It redacts a note of at most 4 KiB (`redact.MaxShortEntry`), the cut symptom and a module's evidence value outside the limit, at most 4 at once, each under 1 MiB of heap (`redact.ShortEntryHeap`, `TestHeapOfAShortEntry`). A longer note or value is not read: the fingerprint takes the fixed `<long note>`, the shown symptom `<long note: N bytes>` and an evidence value `<long value: N bytes>`, always, so neither waits; the note is not cut to 4 KiB, since a cut can end inside a secret, and two long notes of one subject and reason are one Incident (ADR-0039: the fingerprint is a function of the event). The model reads such a note through the events tool. `shadewright_redaction_heap_waits_total` counts the waits. **Memory.** The analyzer's default memory limit is 256Mi (from 128Mi) in the chart and in `config/manager/analyzer.yaml`, its request unchanged, and both install paths set its `GOMEMLIMIT` to 90 percent of it (241591910 bytes, 230.4 MiB), so the limit is 115.2 MiB. **Room**, as design 10.3 states it: 116.5 MiB for the redactor's entries, 4 MiB for the short entries and 77 MiB of Go heap for the rest of the analyzer (design 3.1, measured with the model call off, so with no analysis running) come to 197.5 MiB, about 33 MiB under the Go memory limit; the analyses' own heap is not in the 77 MiB, and the release's lab run records the analyzer's peak with analyses running. This corrects the property of the first decision of 2026-11-22, which said "the limit plus one entry": no entry is added on top of a full limit. Under 256Mi the analyzer logs one warning at start; an entry over the limit still runs alone and can hold up to about 117 MiB, so the risk there is an out-of-memory kill. The match gate of an earlier draft of this change (withholding a text with more matches than its bytes allow) was not built: it withheld ordinary lists of addresses. Nothing new is read, written or granted.

- 2026-11-22, control characters ([#852](https://github.com/shadewright-labs/shadewright/issues/852), decision of 2026-11-22 that replaces the approach of its first build): the Decision is unchanged. **What is hidden only grows.** A control character (Unicode category Cc other than newline and tab) can split a secret's key or value so that the readings of origin/main show it (`pass` NUL `word=mysecretvalue`, a GitHub token a NUL splits, `pass` ESC `word=Hunter2Secret9x` in a container log). Each rule now also reads every text without its controls and adds what it finds; no text and no key is changed before the readings of origin/main run. No value byte origin/main hides is shown: the gates of [design 10](../design/10-security.md) check it against tables written at origin/main. Two named limits: where a span of the added reading begins before a piece that origin/main hides from its first byte, a leading blank of that piece can be kept; and the cut of a log excerpt can keep a few more old bytes than on origin/main (design 10), never bytes a reading found. The collector's readings (the fingerprint, the symptom, a module's evidence value) do not use the added reading and decide exactly as on origin/main, so no fingerprint changes and a secret a control splits in an event note's symptom is shown there as on origin/main. Cluster text is shown with its controls as on origin/main: a log excerpt keeps them, a value shown on a line shows each as a blank, and `get_resource` writes them as JSON escapes. Model text the analyzer stores is redacted as the reply held it and cleaned of controls after its markers are in place. **The cost, measured on this build:** on the generated canonical corpus of #845, kept pieces lost at the entry points (piece by entry point) rose from 9,215 to 19,555, and through `String` from 6,493 to 9,375 (unchanged by the collector's exception: the corpus reaches no collector reading); no secret piece is shown that was hidden before. The largest classes of the 10,340 new ones at the entry points: indentation of other characters 3,071, forms combined 1,951, bracket inside the secret 1,925, a key with format characters or a colon look-alike 1,402, keys on one line 942. Three examples of what is newly hidden: `--password` VT `Abc123 --region west` was `--password` VT `*** --region west` and is `--password` VT `*** *** west` (read without the control, the flag is glued to its value and takes the next word); `app --client-secret \` CR `  hunter2abc --region west` hides the line continuation too (`app --client-secret *** [REDACTED] --region west`); `--password` CR `  - hunter2abc --region west` hides the dash of the list item. **Named limit, as on origin/main:** the decisions on a key alone (`SecretKey`, `SecretCollection`), the forms a tool writes a value in and the cut of shown text do not read the text without its controls, so a secret key name a control splits (an HTTP header or label name `pass` NUL `word`) is not read as a secret key; it moves to v0.7.0, to be built so that it only adds to what origin/main hides. The work of the added reading is 16 to 36 steps per byte on control-dense text and linear from 4 KiB to 1.5 MiB; a match the other readings already hold whole is not held again, and its shapes are in the heap table of [#1087](https://github.com/shadewright-labs/shadewright/issues/1087), under its line at every entry point (design 10).
